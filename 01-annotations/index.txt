# 01. 专属标注与元数据（Nextra v4 派生版）

不同静态网站生成器对“提示框 / 标注（Callouts / Admonitions）”和页面元数据的语法约定存在显著分歧。本文件采用 `.mdx` 扩展名由原始 GFM 母版派生适配至 **Nextra v4 (`4.6.1`)**。

## 1. Frontmatter 元数据与 `format: 'detect'` 双轨编译机制

Nextra v4 默认开启 `mdxOptions.format: 'detect'`，根据文件后缀名智能切换解析严谨度：

- **当前页标题字段**：`title: "01. 专属标注与元数据"`（亦可由同目录 `_meta.js` 覆盖侧边栏显示名，或使用 `sidebarTitle` 单独指定短标题）
- **页面摘要字段**：`description: "..."`（由 `app/[[...mdxPath]]/page.jsx` 的 `generateMetadata` 自动注入 HTML `<meta>`）
- **`.md` vs `.mdx` 派生观察点**：当文件保持 `.md` 后缀时，Nextra 以标准 Markdown + `rehype-raw` 模式编译，正文中裸写 `<id>` 不会报错，但也无法调用 JSX 组件；当改用 `.mdx` 后缀以引入 `<Callout>` 组件时，即进入严格 **MDX 3** 模式，未包裹反引号的裸 `<id>` 或 `{variable}` 会触发 JSX 语法错误。

## 2. 标准提示语义块（Nextra `<Callout>` MDX 组件）

Nextra 不采用三冒号 `:::tip` 指令语法，而是推崇纯正 React / MDX 组件 `<Callout type="info | default | important | warning | error">`：

<Callout type="info">
  默认信息提示块：静态站点对比平台的每个子模块均独立维护 `main`（源码）与 `page`（构建产物）双分支，互不污染提交历史。
</Callout>

<Callout>
  **性能优化建议（默认 Tip 灯泡样式）**：在三冒号体系中需写作 `::: tip 性能优化建议` 或 `:::tip[性能优化建议]`，而在 Nextra `.mdx` 中直接组合 `<Callout>` 组件与加粗标题语义即可。
</Callout>

<Callout type="warning">
  **版本边界注意**：注意区分各派系命名——Nextra `<Callout>` 使用 `info`、`default`（对应 Tip）、`important`、`warning` 与 `error` 五档类型，并支持通过 `emoji` 属性自定义图标。
</Callout>

<Callout type="error">
  **不可逆分支覆盖警告**：自动化流水线在向 `page` 分支推送构建产物时会启用 `force_orphan: true`，切勿在 `page` 分支直接手工修改代码！
</Callout>

## 3. 可折叠详情容器（白名单接管原生 `<details>`）

Nextra v4 内置 `remarkMdxDisableExplicitJsx` 将原生 `<details>` 与 `<summary>` 加入白名单，自动映射为主题内置的带平滑展开动画 `<Details>` 客户端组件：

<details>
<summary>点击展开查看 Nextra 折叠容器与内部 MDX 混排结构</summary>

```mdx
import { Callout } from 'nextra/components'

<Callout type="info">
  Nextra 自动拦截标准 HTML `<details>` 并注入平滑折叠动画与深色模式边框。
</Callout>
```

除了代码块，折叠容器内同样支持列表、表格与数学公式 $f(x) = x^2 + 1$。

</details>

## 4. GitHub 风格引用警报（GFM Alerts）跨框架直通测试
